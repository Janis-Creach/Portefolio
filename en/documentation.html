Configuring VLANs and inter-VLAN routing

Splitting a network into VLANs isolates services (administration, users, guests…). So that they can still communicate, inter-VLAN routing is added, here with a router connected to the switch by a single trunk link (“router on a stick”).

1. Create the VLANs on the switch

One VLAN is created per service and given a descriptive name.

cisco ios

Switch(config)# vlan 10
Switch(config-vlan)# name ADMINISTRATION
Switch(config-vlan)# vlan 20
Switch(config-vlan)# name USERS

2. Assign the ports to the VLANs

The ports connected to the workstations are set to access mode in the appropriate VLAN.

cisco ios

Switch(config)# interface range fa0/1 - 12
Switch(config-if-range)# switchport mode access
Switch(config-if-range)# switchport access vlan 10
Switch(config-if-range)# interface range fa0/13 - 24
Switch(config-if-range)# switchport mode access
Switch(config-if-range)# switchport access vlan 20

3. Create the trunk link to the router

The port connected to the router carries all the VLANs, each frame being tagged with its VLAN number (802.1Q standard).

cisco ios

Switch(config)# interface gi0/1
Switch(config-if)# switchport mode trunk

Good to know: on some switches (for example the Catalyst 3560), you must first enter switchport trunk encapsulation dot1q before setting the port to trunk mode.

4. Configure the router subinterfaces

On the router, one subinterface is created per VLAN. Its IP address serves as the default gateway for the workstations in that VLAN.

cisco ios

Router(config)# interface gi0/0
Router(config-if)# no shutdown
Router(config-if)# interface gi0/0.10
Router(config-subif)# encapsulation dot1Q 10
Router(config-subif)# ip address 192.168.10.254 255.255.255.0
Router(config-subif)# interface gi0/0.20
Router(config-subif)# encapsulation dot1Q 20
Router(config-subif)# ip address 192.168.20.254 255.255.255.0

5. Verify

  • show vlan brief on the switch: each port is in the right VLAN;
  • show interfaces trunk: the link to the router is indeed in trunk mode;
  • a ping from a workstation in VLAN 10 to a workstation in VLAN 20 should get a reply.
